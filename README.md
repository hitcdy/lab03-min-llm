# 实验作业三：手搓最小 LLM —— 使用 CPU 训练（字符级 GPT / 唐诗语料）

《人工智能——深度学习大模型智能体》配套实验 · 实验作业三
学号 2024312149 · 姓名 陈道延 · 完成日期 2026-09-22

不调用任何现成大模型接口，用 PyTorch 从零实现一个字符级最小 GPT（字符分词器 → 因果自注意力
→ Pre-Norm Transformer 块 → 权重绑定的输出层），在 2163 字的唐诗语料（72 首，词表 V = 699）
上做"预测下一个字"的自监督训练，并围绕学习率、层数、嵌入维度、上下文长度、位置编码与采样参数
做控制变量实验，最后手算参数量与代码打印值核对。

## 环境与运行

```bash
python -m venv venv
venv\Scripts\activate            # Windows
pip install torch matplotlib

# 基线 + 8 组对照实验（严格顺序执行，结果写入 results_lab03.json，可中断续跑）
python run_experiments_hw3.py                     # 全部组，约 1 小时（4 线程）
python run_experiments_hw3.py --groups exp4 exp5  # 只跑指定组；加 --force 可重跑

# 单组实验（等价 CLI，参数与指南一致）
python min_llm.py --iters 200 --max_new_tokens 60            # 快速跑通
python min_llm.py --n_layer 4 --iters 1000                   # 改层数
python min_llm.py --no_pos --iters 1000                      # 去掉位置编码（exp5）
python min_llm.py --iters 2000 --save_model                  # 基线（保存权重供采样使用）

# 采样实验：温度 / top-k / 禁止重复 3-gram（图 7、图 8，结果写入 sampling_hw3.json）
python sampling_hw3.py

# 参数量核对（与报告表 3、文末附录一致）
python check_params_hw3.py

# 生成实验报告
python fill_report_hw3.py
```

CPU 线程默认限制为 4（`LAB03_THREADS=4`，见 `min_llm.py` 顶部），用于给整机保留余量；
线程数越大越快，本报告全部数据均在 4 线程下测得。

## 结论要点

- **参数量手算完全对得上**：V×C + T×C + L×12C² = 89,472 + 16,384 + 393,216 = 499,072，
  与代码打印的 502,656 相差 0.71%（< 1%）；差值 3,584 全部来自偏置与 LayerNorm
  （LayerNorm 5×2C = 1,280 + 注意力偏置 2×4C = 1,024 + MLP 偏置 2×5C = 1,280），
  逐模块打印见文末附录。初始 loss 实测 6.5627 ≈ ln 699 = 6.550，验证了 GPT 式初始化
  N(0, 0.02) 的正确性。
- **语料只有 2163 字，训练很快进入"背诵"阶段**：2000 步后 loss 0.026，生成结果是把训练语料里的
  名篇整首背出来（"春眠不觉晓，处处闻啼鸟"），错误只表现为两首诗被拼在一起或中途截断。
  这提示"loss 低"与"会写诗"是两件事，也是本实验后续所有分析的背景。
- **学习率是最"致命"的超参**：1e-4 严重欠拟合（1000 步只到 0.644，生成是破碎词片）；
  1e-2 前期震荡（前 100 步均值 5.33 对基线 3.61），未发散但最终 0.084，仍比基线差 3.2 倍。
- **容量很快过剩，加宽远不如加深划算**：C 从 64 → 256 参数量增 11.7 倍、耗时 2.1 → 12.1 min，
  loss 只从 0.052 降到 0.028（C=256 与基线 0.026 基本持平）；层数 1 → 4 参数量 2.95 倍、
  loss 0.034 → 0.025，收益同样快速递减。在这份小语料上，2 层 128 维已接近上限。
- **位置编码的影响被"背诵"掩盖，但生成细节暴露了它**：去掉位置编码后 loss 仍到 0.031
  （因果掩码残留了部分顺序信息），可是以「月」为提示时出现"月下下扬州""月汉时关"这类重字与漏字，
  说明模型缺少"当前处于句子的第几个字"的显式表示（见思考题 (1)）。
- **采样层面：本模型的最优组合就是基线采样**（T=1.0、top_k=20，distinct-2 最高、重复最低）。
  低温与窄候选只是把同一首诗背得更死，高温则出现"春来终觉浅，绝胜烟豚"这类混拼。
  进阶实验里硬性禁止重复 3-gram 反而没有降低重复指标（0.004 → 0.237），因为本模型的"重复"
  主要来自多次采样落到同一条记忆路径，而不是单段内部循环；硬约束还会把模型推离高概率轨迹，
  产生新的混拼——对比之下，工业界常用的重复惩罚是"软折扣"，更稳妥。

## 关于训练耗时（与指南预估的差异）

指南预估基线 2000 步约 20~30 分钟（作者机器实测 1.3 it/s）。本次 9 组实验合计 56.7 min，
其中基线 8.0 min（4 线程下约 4.2 it/s）。两点说明：

- **线程数与整机负载**：本实验统一限制 4 线程（`LAB03_THREADS=4`）以给整机保留余量；
  实测过程中另一款虚拟化程序（MuMu）占用 CPU 时，吞吐会从 4.2 it/s 掉到 1.4 it/s
  （与指南作者的机器相当），可见"耗时"高度依赖运行时环境，脚本里已按 step 打印 it/s 与 ETA。
- **口径不同**：指南的预估包含读代码、改参数、看图等人工作业时间，56.7 min 只是脚本跑数时间。
